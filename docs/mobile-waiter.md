# Android — 1.0.12

APK: `android/app/build/outputs/apk/debug/app-debug.apk` (копия для установки: `release/POS-Mobile-1.0.12.apk`). Desktop обновлять не требуется.

## Первый запуск

1. Установите APK. Введите логин и пароль кабинета; ФМ и terminal ID для входа на телефоне не нужны. Для авторизации нужен интернет.
2. Если список ролей пуст, создайте PIN администратора, как на desktop. Затем в разделе «Роли» добавьте кассира и официанта. Данные без подключения к компьютеру хранятся на телефоне.
3. При необходимости подключиться к общей кассе откройте «Настройки» → «Сеть терминалов» и введите IP главного компьютера. Телефон и компьютер должны быть в одной сети Wi-Fi. Подключение не требуется для входа по PIN.

При подключении к главному компьютеру общие данные загружаются с него. Локальные данные телефона перед переключением сохраняются в отдельной резервной копии и восстанавливаются при отключении от главного компьютера. Фискальные операции без ФМ на телефоне недоступны.

Для локальной печати настройте Bluetooth-принтер в приложении. При работе через главный компьютер используйте настройки печати общей кассы.

## Обмен с существующей кассой

Авторизация: API веб-кабинета `/auth/sign-in` с логином и паролем. На Android используется native HTTP.

Без подключения данные записываются в локальное хранилище Android. После подключения к главному компьютеру используется существующий `GET/PUT /api/data/:key`; обновления приходят через Socket.IO `data:update`. Новые серверные команды или обновление EXE не нужны.

Перед сохранением телефон читает актуальное состояние и объединяет только изменённые записи. Если тот же заказ уже изменён на кассе, изменения не перезаписываются молча: показывается ошибка, загружаются актуальные данные, локальная попытка сохраняется в резервной записи. Существующий API desktop не предоставляет атомарную блокировку между чтением и записью; эта сборка не добавляет её на сервер.

При потере ответа несохранённые изменения остаются в локальной очереди телефона. После восстановления связи или перезапуска приложение повторяет отправку. До подтверждения нельзя продолжать редактирование заказов. Сменить кассу при непустой очереди нельзя.

## Проверки и сборка

`node scripts/test-mobile-waiter.mjs` — проверки мобильного входа, сохранения desktop-входа с ФМ, маршрутов старого API, WebSocket-обновлений, объединения разных заказов, повторной отправки и защиты от фискальных вызовов. Используется изолированная тестовая касса; рабочая база не затрагивается.

`npm run build`, затем `npx cap sync android`, затем `assembleDebug` через Gradle wrapper на Java 21. Полученный APK подписан отладочным ключом, как предыдущие debug-сборки проекта.

Проверка реального логина, Wi-Fi и физического принтера выполняется на телефоне и кассе пользователя: подключённого Android-устройства в среде сборки нет.
